Title: Project Demonstration (Live Demo)

=====================================================================
1. OPENING SCRIPT
=====================================================================

Good day. We are the proponents of BubbleLink, a laundry service platform developed to help customers browse laundry shops, view services and pricing, place orders online, and track their own transactions inside the system.

For this live demonstration, we will present the actual working functionality of the application. We will not rely on screenshots or slides. Instead, we will demonstrate the live system and explain how the frontend, backend, and database work together.

During this demonstration, we will show the following:

1. Customer registration or login using an existing account
2. Public browsing of available laundry shops
3. Viewing detailed shop information, including services and pricing
4. Interactive frontend behavior during order placement
5. Frontend actions triggering requests to Laravel routes and controllers
6. How backend controllers interact with the database through Eloquent models
7. Persistent and user-specific customer data through order history

Important clarification:
This project is primarily a server-rendered Laravel application enhanced with Alpine.js for frontend interactivity. It demonstrates dynamic user interactions and HTTP requests to Laravel controllers. However, it does not currently use a separate REST API module or a dedicated routes/api.php implementation.

STEP 5. DEMONSTRATE FRONTEND INTERACTIVITY ON THE ORDER FORM
--------------------------------------------------

What to do during the demo:
1. Click Place Order.
2. Show the order form.
3. Change the selected service and observe the price display update.

What to say:
This part demonstrates dynamic frontend behavior. The form responds immediately to customer selections. When the selected service changes, the estimated price updates. Important clarification for panelists:
This is frontend interactivity implemented through Alpine.js. It is not a separate AJAX endpoint. The interface updates immediately on the client side before form submission.

STEP 6. SUBMIT A CUSTOMER ORDER
--------------------------------------------------

What to do during the demo:
1. Fill in the order form.
2. Choose a service.
3. Choose a service mode.
4. Enter the required address and scheduling information.

What to say:
At this point, the customer submits an order. The frontend sends an HTTP POST request to the Laravel backend. The backend validates the input, verifies that the selected service belongs to the selected shop, and then stores the order in the database.

The customer_id is assigned from the authenticated user, making the order user-specific.

What to do during the demo:

4. EXPLANATION FOR AJAX-BASED INTERACTIONS AND API CALLS
=====================================================================

Use this exact explanation during the demo if the panel asks about AJAX or API calls:

Our project currently follows a server-rendered Laravel architecture. Dynamic user interactions are handled on the frontend through Alpine.js. For example, the order form updates price and form fields instantly based on user selection. However, business actions such as registration, login, and order placement are processed through standard Laravel web routes and controller methods rather than through a dedicated REST API module.

Additional clarification:
There is no separate routes/api.php file in the current project. Therefore, when we demonstrate frontend actions triggering backend processing, we are demonstrating HTTP form requests to Laravel controllers rather than standalone API endpoints.
